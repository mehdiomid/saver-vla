Abstract

Vision-language-action (VLA) policies map camera images and a language instruction directly to robot actions. When a grasp slips or an object falls, they usually continue as if nothing happened. SAVER-VLA adds a supervisory layer around a pretrained policy, SmolVLA, instead of retraining it. A verifier monitors the manipulation as it runs and raises an event when the observed state diverges from what the task expects, for example when the object stops moving with the gripper.

Only at that moment does a language-model agent take part. It receives a structured description of the failure, the robot and object geometry, the outcomes of earlier recovery attempts, and the list of skills that are currently executable. It chooses one bounded skill, such as moving to a pregrasp pose, adjusting the grasp offset or handing control back to the policy for a supervised grasp trial. A coordinator validates and executes that choice, verifies the result and returns it to the agent for the next decision.

In controlled fault-injection experiments in LIBERO simulation, this loop recovers from forced object displacement and forced gripper release, replans after an unverified grasp attempt, and, in its most recent version, changes the grasp geometry when the evidence points to a misaligned approach rather than a gripper fault. The experiments also show where agentic recovery breaks down: when the agent’s reasoning is sound but its skill library cannot produce the needed physical correction, or when the coordinator silently overrides its decisions. All results are individual simulation episodes with privileged state, intended to establish feasibility and failure modes rather than statistical performance.

    Method

    SAVER-VLA separates two questions that a single policy normally answers together. SmolVLA decides how the robot should move at 20 Hz. The agent decides what the robot should do next after something has gone wrong, and it is consulted only at recovery boundaries, typically three to nine times per episode. It never produces motor commands.

    What the agent sees and returns

    At each decision the coordinator sends a JSON observation: the grasp state (for example GRASP_LOST), the end-effector–object distance and XY offset, the last skill and its result, the outcome of any supervised grasp trial, the measured mismatch between requested and executed gripper commands, attempt counts, and two lists: available_actions and unavailable_actions with the reason each one is blocked. From Phase 6.4 on, the name of the injected fault is withheld. The agent answers through a strict JSON schema with a skill, a variant, its reason, and the outcome it expects.

    Every skill acts on live simulator state, issues bounded relative commands through the Panda’s operational-space controller (at most 5 cm per step), and has its own timeout and attempt budget. A skill reporting REACHED means only that it reached its target pose. It does not mean the object was grasped, a distinction the first agents got wrong.

    Reasoning quality matters: the same state, two models

    In Phase 6.2 we gave the agent two new skills, reassessment and grasp-offset adjustment, and ran GPT-5.2 and GPT-5.5 on the same gripper-release episode. Both reached the near-grasp pose at step 186 with the can on the table, about 8 cm from the gripper, and no grasp attempted yet.

    GPT-5.2 read “no verified grasp yet” as evidence that the approach had failed. GPT-5.5 distinguished preparing for a grasp from attempting one. Both episodes ended with LIBERO success, but for GPT-5.2 that came only after it aborted and SmolVLA continued on its own, so we do not count it as an agent-supervised recovery. This is one episode per model. GPT-5.2’s first three decisions in Phase 6.1 matched GPT-5.5’s and produced the same trajectory shown on the right.

    Same symptom, different evidence, different strategy

    A fixed recovery script responds to a failed grasp the same way every time. The question we care most about is whether the agent can tell different causes apart from what it can observe.     What we learned

    Explicit recovery is necessary; restarting the policy is not enough

    Clearing SmolVLA’s action queue makes it re-plan from the current image, but the instruction still describes the original task and the policy did not return to the dropped can. Moving the arm back near the object, then handing control back, was what let the learned policy regrasp.

    Orchestration alone does not show the value of an agent

    Under the first two faults the agent chose the same three-skill sequence a script would, and both succeeded. An LLM that reproduces a fixed plan adds latency without adding capability. The interesting cases are those where the right action depends on evidence a script was not written for.

    Feedback and an honest outcome vocabulary drive replanning

    Agents replanned well once the coordinator separated “reached the approach pose” from “attempted a grasp and failed,” and reported supervised grasp trials as verified or not. Earlier, a persistent GRASP_LOST flag led GPT-5.2 to recover from failures that had not happened.

    An agent can only be as capable as its skills and constraints allow

    In 6.4b the agent’s request was sound but invisible attempt limits overrode it; in 6.5 its choice was sound but the skill ended at the wrong height. Neither was a reasoning error. Exposing executable capabilities to the agent, logging requested and executed skills separately, and fixing the skill itself each changed the outcome more than any prompt change did.

    Task success is not the same as recovery success

    Three runs reached LIBERO success after the agent had given up, because SmolVLA continued on its own. We report agent decisions, skill outcomes and task outcomes separately so that a successful episode is not credited to the agent by default.

    Limitations and next steps

    Each result above is a single episode of a single LIBERO task, so none of them supports a success-rate claim. The verifier and the skills use privileged simulator state (object and end-effector positions, and requested versus executed gripper commands) rather than camera-based perception. Faults are injected, which keeps them controlled and repeatable but leaves open how the system handles failures that arise naturally. Several attempt limits and distance thresholds were set by hand.

    The next stage is a matched evaluation across fault types and magnitudes and multiple seeds, comparing SmolVLA alone, a scripted recovery baseline that sees the same observations, and the agent, including smaller and faster models. We will measure task success, recovery success conditional on a failure, decision quality, unnecessary interventions, and the cost of reasoning in time and API calls. After that, the privileged state will be replaced with visual estimates.
